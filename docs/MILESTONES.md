验证：18 项测试通过，包含 3 个真实 MCAP 的两种采样方案、合成 H.264 B 帧、收据校验与失败场景；相关代码 ruff 检查通过。依赖锁文件检查通过。

数据以本地 verification.json 为索引依据。原始数据保持只读；完整下载不等于专家实验条件全部满足。只有人工确认且与测试集独立的专家样例才能用于严格审核。

开发要求“代码要精简，不要冗余”已保存为 .agents/skills/concise-code/SKILL.md，并通过 skill-creator 校验。

提交：`9718070`。

已实现分离的通用/任务提示词、五条专家引用、JSON 严格校验、候选时间证据校验、保守审核策略、服务异常区分及人工专家批准规则。

真实验证的结构化记录保存在忽略提交的 artifacts/checks/qwen-generic-smoke.json。

提交：`3545432`。

## M3：Web、命令行与评测

已实现采集选择与画面预览页面、按 episode_id 审核的 Web API、共享 CLI、实验候选生成和离线评测报告。默认专家清单已生成，保持未批准状态；首次无配置启动可用。

验证：全量 `CITADEL_REAL_MCAP=1 .venv/bin/python -m pytest -q` 得到 **121 passed**，包含三个真实 MCAP 与四个完整集成场景。全项目 `ruff check src tests` 和补丁格式检查通过。测试依赖产生两条弃用提示，不影响通过。

本地 HTTP 启动检查通过：首页、健康检查、277 条记录/10 个动作的列表，以及真实记录审核响应和结果落盘。CLI 抽帧实际导出 4 张 JPEG，保持源时间戳。真实 Qwen 连通性已在 M2 单独验证。

此处 277 条是本次准备清单时的本地快照，不是数据源的永久计数。默认实验清单含 39 条专家候选、238 条独立测试样本（24 条 baseline 候选、214 条 exploratory）；候选审批或具体任务样本不足时，审核保持 uncertain，不能将工程测试通过解释为完整分类效果已经达标。
