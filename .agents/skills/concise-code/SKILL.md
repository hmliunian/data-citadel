---
name: concise-code
description: 在编写、修改或审查代码时落实用户的精简偏好，减少重复逻辑和无必要抽象，同时保持可读性与现有行为。
---

用户要求：**代码要精简，不要冗余。**

- 围绕当前需求实现；新增类、配置项、依赖或间接调用应有具体用途。
- 相同业务规则只维护一份，优先复用已有函数和数据模型。
- 用清楚的命名和直接的控制流程表达逻辑；仅在确有多个实现或需要隔离依赖时引入接口。
- 删除本次工作产生的死代码、未使用变量、重复转换和只复述代码的注释；保留必要的错误处理与数据校验。
- 测试验证可观察行为、真实故障或关键约束，避免逐行复写实现。

交付前检查改动中是否存在可合并的重复逻辑、无调用者的代码或过度拆分。精简不得改变已经约定的功能和可靠性要求。
