---
name: concise-code
description: 开发或修改 Data Citadel 时保持代码精简，并在新功能验证通过后及时进行本地 Git 提交。
---

- 以 agent.md 的已确认需求为范围；代码直白、命名清楚，相同规则只维护一份。
- 抽象、配置和依赖必须服务当前需求；避免重复封装、无调用者代码和预先搭建的框架。
- 新任务通过任务规则扩展，共用数据、视频和接口流程；通用代码不写死任务物体或 task_code。
- 每次完成一个可独立运行的新功能或修复，先运行相关测试和项目检查；通过后立即本地 commit，不积压多个功能。
- 提交前检查 diff，仅暂存该功能的明确路径；不夹带无关改动、凭据、原始数据和运行产物。
- 提交信息使用简短 Conventional Commits；报告提交号与验证结果。推送需要用户授权。
- 测试失败先修复；测试应验证业务行为和真实边界，避免复写实现或为简单文字修改增加测试。
