## 项目简介

Data Citadel（数据瑞城）用于审核机器人任务采集数据。项目以人工确认的正确样例作为专家参考，结合 Qwen 多模态模型识别视频中的通用质量问题和任务特有问题，并通过统一接口返回审核结果。

当前阶段优先支持**原子操作**，目标是严格筛选可作为 ground truth 的正确数据：只有结果明确、过程完整且画面质量合格的样例才会被判定为正确；错误或无法可靠确认的样例进入问题数据集合。

## 审核范围

首阶段选取 7 个原子任务进行验证，并为每个任务整理人工审核过的专家样例。系统重点识别以下问题：

| 类型 | 含义 | 建议处理 |
| --- | --- | --- |
| 数据缺失 | 必需字段、视频流或其他数据不存在 | 排查采集软硬件 |
| 画面模糊 | 图像模糊，无法可靠判断动作 | 改进采集规范并培训采集员 |
| 采集内容不符合要求 | 执行内容与任务要求不一致 | 明确任务说明并培训采集员 |
| 动作不完整 | 操作过早结束或关键步骤未完成 | 统计问题并培训采集员 |
| 反复重试 | 中途失败或多次尝试后最终成功 | 单独标记并保留其训练价值 |
| 标注信息错误 | 标签、任务描述或其他标注与实际内容不符 | 改进标注流程 |
| 其他问题 | 操作失败等未被上述类型覆盖的问题 | 记录原因并进入人工复核 |

## 审核流程

1. 根据任务 ID 加载视频、标注和相关元数据。
2. 校验必需字段与视觉数据是否完整。
3. 按抽帧策略提取主视角画面。
4. 使用通用提示词检测模糊、遮挡摄像头、长时间静止等质量问题。
5. 结合专家样例判断任务内容和动作过程是否正确、完整。
6. 输出正确、错误或无法确认的结论，并给出问题类型和理由。

## 抽帧策略

- **基础方案**：仅使用一路主视角，每 2 秒抽取一帧。
- **关键帧方案**：提取首尾帧，以及夹爪开始/结束闭合、开始/结束张开等关键时刻。
- **专家样例**：可每 1 秒抽取一帧，为模型提供更完整、精确的操作参考。

后续将通过实验比较不同策略在准确率、调用成本和处理时延上的差异。

## 接口约定

系统按 Web API 形式设计。预期输入为任务 ID，输出为结构化审核结果，例如：

```json
{
  "task_id": "example-task-id"
}
```

```json
{
  "task_id": "example-task-id",
  "verdict": "incorrect",
  "error_type": "incomplete_action",
  "reason": "动作在目标状态完成前结束",
  "confidence": 0.93
}
```

建议的 `verdict` 取值为 `correct`、`incorrect` 和 `uncertain`。只有高置信度样例才输出 `correct`，`uncertain` 样例交由人工复核。

## 评测方案

- 每个任务准备人工确认的正确样例，并选取至少 5 条作为专家参考。
- 为“正确”及 7 类问题分别准备 5 条测试样例。
- 优先评估正确数据的精确率，避免错误或模糊样例混入 ground truth。
- 在能够稳定区分正确与错误后，再评估各错误类型的分类能力。
- 对“反复重试”单独统计，避免误删具有训练价值的数据。

## 规划中的项目结构

```text
data_citadel/
├── app/                 # Web API 与请求模型
├── core/                # 配置、领域模型和审核结果定义
├── reviewers/           # 通用审核与任务特有审核逻辑
├── sampling/            # 视频抽帧与关键帧提取
├── prompts/             # 通用及任务级提示词
├── tests/               # 单元测试与评测用例
├── data_citadel.png     # 项目标识
└── README.md
```

目录会随着实现逐步建立；业务逻辑、模型调用、视频处理和接口层应保持解耦，便于测试与替换。

## 本地配置

模型凭据只应通过环境变量或未纳入版本控制的本地配置提供，例如：

```bash
export QWEN_API_KEY="your-api-key"
export DATASET_ROOT="/path/to/datasets"
```

请勿在代码、README、日志或提交记录中保存真实 API Key。仓库已忽略本地 `Qwen-api/` 与 `qwen-api/` 目录。
